# Спринт 2: Аналитика, Фильтры и Оптимизация
Твоя задача — превратить наш дневник в профессиональный аналитический инструмент. Мы создадим новую страницу аналитики и добавим сложную систему фильтрации, состояние которой будет сохраняться при навигации.

### 1. Управление состоянием (Redux Toolkit Slices)
Тебе предстоит написать свои первые классические редюсеры и слайсы.

1. Глобальные фильтры: Создай слайс для хранения параметров фильтрации сделок (поиск по инструменту, фильтр по датам, фильтр по алгоритму). Если пользователь настроил фильтры на главной странице, перешел на страницу аналитики и вернулся обратно — фильтры не должны сброситься.

2. Тема приложения: Реализуй управление светлой/темной темой через отдельный глобальный слайс. Состояние должно синхронизироваться с localStorage (при загрузке приложения стор инициализируется значением из памяти).

### 2. Продвинутая верстка и Layout
В этом спринте мы строим сложный интерфейс без использования UI-библиотек.

1. Страница Аналитики (Grid): Реализуй дашборд с метриками (Общий PnL, Винрейт, Лучшая сделка). Используй display: grid и grid-template-areas, чтобы расположить виджеты. Сделай так, чтобы на мобильных устройствах сетка плавно перестраивалась в одну колонку.

2. Сайдбар фильтров (Offcanvas/Drawer): Сделай панель фильтров, которая выезжает сбоку по клику на кнопку. Реализуй плавную анимацию появления и скрытия исключительно на CSS (без библиотек анимации).

3. Долги по UI: Добавь страницу 404 (Not Found) и настрой роутинг. Проставь aria-label для всех кнопок-иконок (например, переключателю темы), чтобы скринридеры понимали их назначение.

### 3. Оптимизация производительности
Я обновил бэкенд так, что теперь он отдает 10 000 сделок разом (*спасибо папаша (с) Я*). Обычный рендер таблицы на React от такого количества DOM-узлов начнет сильно тормозить.

1. Виртуализация списка: Оптимизируй рендер таблицы сделок на главной странице. Отрисовывай только те строки, которые сейчас находятся в области видимости (Viewport). Можешь попробовать написать логику сам через IntersectionObserver или взять стандартное решение вроде react-window.

2. Оптимизация вычислений: На странице аналитики тебе придется высчитывать метрики на основе массива из 10 000 элементов. Используй useMemo, чтобы тяжелые математические расчеты не запускались при каждом чихе (например, при открытии/закрытии сайдбара), а пересчитывались только при изменении массива сделок или фильтров.
